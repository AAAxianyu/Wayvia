## 设备历史

SQLite migration 4 增加设备稳定 ID 下的分钟/小时桶和订阅拉取声明；保留 migration 3 累计值和水位，不伪造过去的历史。原生本地 API 投影与认证边界沿用 007，不收集目标网站、地址、正文、原始 User-Agent 或认证秘密。

连续成功样本间隔不超过 10 秒，且核心代次不变时，已知连接的非负计数器增量、或本间隔新建连接的计数，可归入采样结束桶。跨桶间隔标记 `cross_bucket_interval`，不声称字节精确发生在该分钟。初始快照、重启、缺测及同代次计数器重置的字节进入 `unallocated_*`；它们是累计核对量，不能据其桶时间归因业务负载。重置按上下行分别处理，避免重计未重置方向；接受新水位以便后续继续计数。

覆盖率是连续采样时间，按桶边界切分，不证明所有连接最终计数都已取得。连接数保存采样峰值/最后值；未知桶的字节和连接数为 null，缺测不等于零或离线。`last_used_at` 只推进可定位的流量增量，不为初始快照制造“刚使用”。物理设备在线、用户正在操作和国内直连负载仍未知；稳定 ID 代表凭据身份。

分钟/客户端声明保留 30 天，小时保留 365 天。两个粒度在同一事务内累计，清理不重新聚合，重复执行不会重计。查询也执行期限过滤，即使采集停止仍不导出过期明细；物理清理发生在后续写入或显式 `history-prune`。最多查询 10000 桶/10000 声明，按完整桶返回并注明查询的边界桶，禁止按比例推算部分桶。订阅拉取计数与实际使用独立；客户端只保留少量已知家族和数字版本的未认证声明，每家族每分钟最多一行（版本为该分钟最后声明）。

## 独立告警与完整性

`alerts evaluate` 是独立单次、只读源证据评估；不依赖采集循环存活，不启动采集、不操作服务或网络。显式配置两个预期角色、原租期目录和诊断库，校验 run/role/path/revision/generation 绑定。缺少一端必须作为缺失源配置，不能省略后声称完整。主动 `stop.json` 和原截止时间优先，终止范围保持安静，不续期、不恢复旧任务。

监控仅增加 best-effort `health_degraded`/`health_healthy` 事实；所有层健康与单层 `probe_healthy` 区分，单层成功不能解除整链降级。采集器可读取未过期监控快照，保留原 `monitored_at`，不为旧检查刷新时间。新鲜降级/保护失败/恢复失败产生健康告警，完整健康或恢复成功才能解除；源不可读、过期或失联不会解除业务告警。单次评估间发生又恢复的短暂降级仍保留打开/恢复通知。角色水位阻止迟到失败重放，持续同一降级跨有界证据窗口保持一个告警事件，最新触发窗口引用另列；显式共同 incident ID 合并两端；仅时间相邻不作因果归并。

完整性单独报告：采集异常停止、采样心跳、监控证据过期、源覆盖率/日志空洞、本地磁盘可用空间、证据页预算和未轮转明细、持久化失败、已跟踪事件证据到期，以及可选统计心跳。采集器丢失不被命名为业务断连。本地副本磁盘空间不代表对端磁盘；未能读取的源、未知偏移和窗口缺口明确展示。缺失范围通知最多列 32 段并给出总数；完整范围仍可用 16 的时间线查询。

告警数据库独立 owner-private 0600/0700，DELETE journal、FULL 同步、secure_delete，4096 页大小与 64 MiB 数据页上限（另留至多同量 rollback journal）。状态/通知各最多 4096 条，单消息最多 48 KiB；满载或持久化失败明确非零，事务回滚，不丢弃新鲜待投递通知。正常状态不建消息；相同原因不重复入队，当前覆盖率仍更新。通知保存发生/检测时间、角色与 incident 引用、时窗、覆盖率、缺口、不确定项和后续操作。源证据查询、快照与摘要不修改源库。

## 时间测量扩展

旧公共证据 v1 的未测偏移仍为 null，旧记录不增添字段，从而保持重导入幂等。显式 `--measure-clock-offset` 在原有有界命令执行器里只读 `chronyc -n tracking`（固定 C locale）；不会安装 daemon 或调整时间。使用 System time 的符号与数值，拒绝非 Normal、无效 stratum、本地参考、过旧参考和未知格式。只保存偏移、测量来源和测量时间；不保存 NTP 主机/IP 或原文。偏移字段须带识别的来源、新鲜测量时间和 synchronized 状态，否则投影为未知。

这是对 008/009 “尚未实现偏移测量”的有界扩展。两端比较的是各自主机报告的 NTP 估计偏移之差，不是精确单向延迟或已证明的跨机时钟精度。测量关闭时保持未知，可由告警配置要求偏移可用。参考 [chrony 4.5 官方 tracking 文档](https://chrony-project.org/doc/4.5/chronyc.html)；只验证格式夹具，未查询实际 chrony 版本或实测时钟。

## 显式投递与终止规则

评估只写持久 outbox。投递须私有配置指定目录或 HTTPS 渠道，并显式 `--authorize-send`；本轮 HTTPS 仅 MockTransport，不发送真实消息。HTTPS 强制 TLS、禁用环境代理/重定向、有界超时，不接受带用户名、密码、query 或 fragment 的 URL；Bearer 从私有 JSON 文件读取，不存入状态/日志。最多一次调用尝试 8 条，每条一次；失败保留同一 event ID/idempotency key，下次显式调用重试。目录投递采用独占 0600 文件并校验已有相同内容。崩溃后的语义为至少一次，接收者需按 event ID 去重。

投递 TTL 为 7 天；过期未发通知保持可见并返回非零，禁止作为新告警重放，只能显式 `discard-expired` 清除并累计清理数。已投递记录和已结束状态到期清理。watchdog 单次检查评估心跳，可发现评估进程停止、时钟回退或状态写入失败；不能由已停止的进程自身保证送达。未来需要独立、明确授权的调度/渠道及双方传输验收。本轮不创建 automation、timer 或 daemon，不恢复 heartbeat。
