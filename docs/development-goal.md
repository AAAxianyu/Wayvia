# Wayvia 开发 Goal 指令

更新于 2026 年 10 月 12 日

在包含 [产品开发文档](development.md) 的 Wayvia 仓库中打开 Codex 任务，将下面整段作为一条消息提交。/goal 后面是持续目标及完成条件；它会启动开发，而本文件本身只提供可复制的指令。[OpenAI Goals 使用说明](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)

```text
/goal 在当前 Wayvia 仓库中，依据 docs/design.md 和 docs/development.md，把项目从文档构建为可运行、可配置、可测试的软件，完成 M0 至 M5 的软件交付标准，持续实现功能直到有证据满足完成条件，不能停在目录脚手架、空接口或演示页面。

开始时检查仓库状态与已有 AGENTS.md，阅读上述两份文档及 docs/product-overview.md。采用开发文档的 Python、uv、Pydantic、Typer、FastAPI、SQLite 和 Linux 适配基线；实际依赖与外部组件使用锁定的稳定版本。普通实现细节自主决定并记录，架构冲突及时提出，同时继续独立工作。

必须保持：国内与本地资源在终端直连；国外路径为终端→阿里云接入→阿里云 OpenVPN→阿里云代理→日本代理→日本 OpenVPN→目标。日本同时运行代理和 VPN。终端仅连接阿里云。代理故障时受保护业务不自动直连，国内访问继续工作。DNS、IPv6、回程与管理路径按设计隔离。

按 M0 至 M5 依次交付可安装工程、CLI、配置与规则编译、设备与独立凭据、格式适配与完整配置导出、私人订阅 API、真实代理及 VPN 适配、Linux 网络事务和独立回退、分层诊断、隔离双层实验，以及安装运维文档。先做一个从配置到设备到导出到 API 的真实闭环，再接通网络执行。数据面复用成熟组件，不自行发明加密协议。

实现并运行 make check、make demo、make test-configs 和可用环境中的 make test-lab。测试覆盖国内直连、双层顺序、DNS/IPv6、UDP、回程、两层分别断开、令牌与设备权限分别撤销、超时回退和重启恢复。fake 仅用于明确标记的测试或演示，生产模式拒绝 fake；未实现能力返回错误，不能返回伪造成功。配置校验必须使用锁定版本的真实组件。

维护 docs/implementation-status.md、compatibility.yaml 和 docs/validation/。每个阶段记录改动、命令、结果、证据和下一步，修复失败后继续。缺少服务器凭据、域名或手机时，先完成所有不依赖这些输入的软件任务。Linux 实验环境缺失时尝试当前授权内的隔离环境或 CI 路径；确实无法运行则保留实验与缺失证据，明确标记 M4 环境阻塞。软件交付完成、受控链路通过、真实环境验收是三个独立结论。

操作范围为仓库、本地开发服务和明确的一次性测试环境。不要改变开发机默认路由、全局防火墙或现有 VPN，不要连接或改动未经本任务指定的真实服务器，不要提交凭据。保持对外介绍的正式产品口吻。使用 codex/ 开发分支并保留用户已有改动。

最终按开发文档第 13 节逐项核对：核心实现完整、非特权检查和真实配置校验通过、设备与订阅闭环可运行、网络适配与恢复代码可执行、实验有结果或明确的环境阻塞证据、文档可复现。交付运行方式、验证结果、剩余实网输入与风险。若必需的软件门禁仍失败，继续修复；确无可执行路径时报告具体阻塞和最小所需输入，不把未完成工作标为完成。
```

## 交付预期

这条指令要求完成真实的软件功能与可执行的网络适配，受控实验尽可能在隔离 Linux 环境中取得证据。它不以生产服务器凭据为开发启动条件，也不把软件完成等同于真实网络验收完成。

项目进入真实部署时，再提供两台服务器的系统信息、域名、认证方式与明确的目标主机授权，并继续执行开发文档中的 M6 验收。
