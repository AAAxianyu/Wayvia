## 实现判断

当前可以进入 M6 的专用云主机试运行。已有 M0–M5 软件与完整隔离实验通过证据；M6 实网和手机验收尚未执行，M7 OpenWrt 未实现／验收。

已实现：

- 严格配置、国内与本地直连策略、默认代理、DNS 分流，以及 sing-box/mihomo 完整配置导出。
- SQLite 控制面、设备独立凭据、轮换／撤销、私人订阅、CLI/API、显式配置发布。
- 日本 sing-box Trojan TLS 承载入口与 OpenVPN 服务端；阿里云 sing-box 接入、独立业务桥接、OpenVPN 客户端、v2rayA/core 承载。
- 固定网络动作、资源归属与冲突检查、独立超时回退、运行代次、监控和恢复；发布检查双方同 revision、ACTIVE 和新鲜证据。
- 软件安装、同版本重装、有限卸载和恢复日志。

需要保留的限制：

- 系统安装器限定 Ubuntu 24.04，并检查锁定的 uv/OpenVPN 版本；其他发行版需要适配验证。
- VPN 底层为 TCP over SOCKS5 over Trojan TLS。隧道内 TCP/UDP 有实验验证；不等同于支持 UDP VPN 底层或实时业务性能保证。
- 国外代理 IPv6 被阻断；国内直连 IPv6 有独立规则与实验。
- mihomo 的解析与 DNS 验证不能替代完整手机 TUN 验收；Android/iPhone 必须选定应用及版本。
- 设备轮换／撤销通过入口重启关闭旧会话，会影响其他在线设备；仅撤销订阅链接不会撤销已导入的代理密码。
- 真实整机重启、跨版本升级、目标 Wi-Fi／蜂窝切换、性能与费用没有实网验收。
- HTTPS 订阅反向代理、生产证书签发／续期和云端规则需在部署时配置。不能将软件布局安装完成等同于网络部署完成。

## 拿到两台服务器后的顺序

1. **目标确认与只读体检。** 确认阿里云入口与日本出口的 IP、SSH 方式、sudo、系统和架构、现有服务、可接受停机范围；检查监听、默认路由、已有 VPN、转发状态、TUN、nftables、systemd、磁盘和时间同步。网络故障实验仅在明确可丢弃的试运行实例／隔离 VM 中进行。先保存现状和恢复入口。
2. **部署材料。** 固定源码及组件版本，准备两个服务域名、TLS 证书、独立 VPN CA 和双端证书、服务器承载密码、校园域名／网段／DNS，以及受控外部探针。两端保持相同逻辑配置 revision，按角色分发秘密；手机仅取得自己的阿里云接入凭据。
3. **日本 exit。** 先安装不活跃的软件布局，准备证书和专属服务，显式配置授权出口的 IPv4 转发。公网 Trojan 承载端口仅允许阿里云公网来源；OpenVPN 仅监听 `127.0.0.1:1194/TCP`。代理只允许该目标，VPN 子网 NAT 限定实际出口接口。生成 plan、apply、验证、confirm。
4. **阿里云 ingress。** 公网接入默认采用 Trojan TLS 443。入口及回包留在宿主；业务进入 `wayvia-egress` 内的桥接与 OpenVPN；VPN 底层通过宿主 v2rayA/core 到日本代理。先安装保护，再建立链路；管理连接与主机默认路由保持独立。生成 plan、apply、验证、confirm。
5. **单设备试用与配置发布。** 先创建测试设备并完成 reconcile；待双方当前代次及 monitor 证据新鲜，通过 SSH 传递日本状态并显式 publish，再导出文件让选定手机导入。文件导入验收后开放私人 HTTPS 订阅。订阅 HTTPS 使用独立监听端口／地址，避免与 443 Trojan listener 抢占；管理 API、agent、SOCKS 和 v2rayA 管理端口保持私有。
6. **验收后扩大使用。** 国内／校园目标从终端当前网络直连；国外目标观察到日本出口。联合目标日志、连接与规则计数证明 VPN 经过代理、代理只到 VPN，不能仅凭出口 IP 判定双层顺序。检查 DNS、IPv6、TCP/UDP、两层分别中断后的阻断与恢复、认证错误、设备与订阅分别撤销、未确认回退、整机重启和切网。测量时延、吞吐、丢包、重连时间及两端流量，先小范围试用，再按验收结果开放更多设备。

手机验收先建立蜂窝与普通 Wi-Fi 基线，再进入目标校园网络。设计记录中的“校园网启用 Clash 后超时、蜂窝可用”仍需复现并分层定位，当前证据不能将它直接归因于 DPI 或账号封禁。

订阅发布与两个服务器的事务是分开的；部署失败保持上次发布快照，不宣称跨主机原子提交。故障保护只覆盖客户端正常运行并接管的业务，用户主动停用客户端后的行为依赖手机系统设置。

## 开始实网工作所需输入

- 两台目标主机的 SSH 别名或 IP、用户、已有 SSH 密钥文件路径及允许操作范围；不在聊天或仓库粘贴私钥。
- 系统／架构、现有业务与 VPN、是否专用且可丢弃、端口、带宽与流量限制。
- 接入及承载域名、DNS 管理方式和证书条件。
- Android/iPhone 应用及版本；目标网络、校园规则、主要应用、并发设备数。
- 受控外部测试端点，或允许使用的测试服务与流量预算。

云安全组的协议、端口与来源 IP 范围按目标实例现状设置，参考 [阿里云安全组规则](https://www.alibabacloud.com/help/zh/ecs/user-guide/security-group-rules)。OpenVPN SOCKS 支持的官方依据见 [OpenVPN 2.6 手册](https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual.html)；Wayvia 当前接受的具体组合仍以仓库锁定版本和测试为准。
