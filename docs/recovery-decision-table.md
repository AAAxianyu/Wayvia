# 待办 12：按失败层恢复决策表

日期：2026-10-25 America/Los_Angeles。状态：设计草案，**未实现、未部署**。故障/重启实验继续暂缓。

当前 `monitor()` 遇到必需探针失败会进入 DEGRADED，`protect()` 停止入口或出口代理；下一轮 `_rebuild()` 重放整条计划。因此只减少 `_rebuild()` 的重启对象，仍不能消除保护阶段的会话中断。本表同时区分保护、归因证据、恢复范围和恢复后的开放条件。

## 优先规则

1. 只允许当前角色、当前代次持锁操作；旧代次的 monitor/恢复不得操作当前服务。
2. `EXPLICIT_INGRESS_BLOCK` 和 `DEVICE_SYNC_FAILED` 优先于所有普通故障。普通探针恢复、采集器恢复和主机重启均不能清除它们；设备检查点始终覆盖旧计划凭据。
3. 必需检查失败仍按当前规则保护业务。减少服务停止需要先证明独立保护资源足以维持 fail-closed；本次不删除 `protect()`、放宽阈值或增加“健康宽限”。
4. 失败阶段不等于根因。单条 HTTP_TIMEOUT、curl 35 或某个 TCP RTT 不能证明 carrier/VPN/日本主机损坏。只有额外的同代次组件证据支持时才缩小修复对象。
5. 拟议恢复保持 VPN-over-proxy、国内直连、服务器秘密边界与管理回程；不使用物理直出、跳过证书、缓存成功或恢复撤销凭据。

## 拟议决策

下表中的“候选动作”均待实现；当前代码继续执行既有保护和整链恢复。

| 触发与证据 | 保护要求 | 最小候选动作 | 升级条件与限制 |
| --- | --- | --- | --- |
| 旧 generation、过期/缺失证据 | 不允许旧任务改变现役服务；证据不得用于发布 | 当前代次重新取证 | 不能把更新时间当成探针完成；不凭旧失败重启 |
| 采集器到期/停止、磁盘不足、观测空洞 | 观测层失效不直接改变数据面健康策略 | 记录缺测；仅在原授权期限和 lifecycle 规则允许时恢复采集 | 禁止重开已结束任务或把采集失联计作业务断连；告警留给 18 |
| 中继清理错误，但新鲜响应已完整且身份正确 | 使用 ADR 006 的既有严格结果判定 | 保留请求结果与清理错误，通常无需服务恢复 | TLS/证书异常、身份不符、响应不完整或越期不能走此分支 |
| 单个目标传输失败、备用成功 | 既有总预算及身份校验不变 | 保留失败 attempt，无需重建 | 备用只适用于已允许的错误；不额外增加端点、重试或阈值 |
| 所有 HTTP 目标超时，组件是否损坏未知 | 维持受保护业务阻断 | 先核对同代次 carrier、VPN 会话、桥接及 DNS 证据；暂不猜测修复对象 | 不因“发生超时”直接判某主机故障；若没有足够证据，保持保护并进入有界人工/恢复流程 |
| carrier 进程/API 确认不可用 | 保留 namespace guard 和固定承载路径 | 恢复 carrier，观察既有 VPN 是否自行重连 | 仅 VPN 不能恢复时扩大到 VPN；不能先例行重启仍健康的入口/桥接 |
| VPN 会话/TUN 确认失效，carrier 健康 | 阻止业务物理 fallback，保留 carrier | 恢复 VPN 并校验服务端身份和已认证会话 | 只有依赖组件就绪失败才修复对应桥接/入口；OpenVPN 不得直连日本 VPN |
| 入口或桥接进程确认失效，carrier/VPN 健康 | 在独立 guard 下启动必要 listener | 仅恢复对应组件并同步最新设备凭据 | 凭据同步失败转安全阻断；不得通过旧配置恢复已撤销会话 |
| DNS 失败，HTTP/VPN 等证据仍健康 | 仍按既有必需检查失败处理 | 验证指定解析器、路径及相应组件；仅修复已确认失效依赖 | DNS 错误不直接授权重启全部代理/VPN，不绕过代理解析 |
| 证书、身份或未知 TLS 异常 | 保持保护，不使用成功缓存 | 保存有限分类，核验受限证书/身份及配置一致性 | 不能按传输抖动无限重试；证书/身份不符无备用掩盖 |
| guard、路由归属、回程或配置一致性不可信 | 采用严格保护，必要时停止受影响服务 | 通过已有事务机制恢复自有资源并重新验证 | 保护未确认或恢复失败进入 RECOVERY_REQUIRED；禁止改开发宿主或非自有规则 |
| 显式阻断或设备同步失败 | 持久阻断优先 | 仅获授权且成功的凭据/配置协调可以解除相应阻断 | monitor、重启和普通网络恢复不能解除 |

## 状态机实现前必须明确的接口

- `ProtectionDecision`：阻断原因、保护资源确认结果、是否必须停止入口/出口；持久化先于副作用。先评估 ADR 002 的“停止入口”是否需要新 ADR 修订，不能静默覆盖。
- `RecoveryDecision`：所依据的事件/代次、已确认失败的组件、最小动作集、升级条件和总预算。unknown 必须有明确保守路径，不伪造精确归因。
- `RecoveryOutcome`：实际停止/启动的组件、保护开始/结束、尝试次数、最新凭据修订及失败原因。service started 不等于业务恢复。
- 重新开放：安全阻断已由合法协调解除；保护资源正确；必要组件在保护内启动；当前代次必需探针获得新鲜证据后方可 ACTIVE。发布继续遵守 ADR 004 双端证据要求。

## 后续验收门槛

软件回归应覆盖决策优先级、unknown、有限升级、过期/错代次和中断后的幂等恢复。减少保护性停服务的实现必须另行取得一次性 Linux 环境的负向证据：代理/VPN 分别失效时无直出、承载顺序不变、撤销不复活、保护自身失败时不开放，以及连续恢复/并发代次不会互相覆盖。

以上隔离故障实验与真实重启验收本次均不执行。阶段 15 的证据可以帮助选择候选动作，但不能替代这些安全验收，也不能证明 JXY 最初超时的根因已经解决。
