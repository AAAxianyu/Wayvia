# 07 收紧订阅与管理接口边界

Status: open
Scope: planned
Priority: must-minimum
Blocked by: none

## 问题

公网管理路径由反向代理拦截，但订阅与管理能力仍由同一控制服务提供，进程可访问控制面设备秘密；订阅信息链接由请求 URL 构造，Host 信任边界需要明确。

## 必须的基础检查

- [ ] 验证公开入口不暴露管理路径，管理接口保持受限本地路径和管理员鉴权；评估应用层增加订阅专用路由是否确有必要，避免将现有本地管理功能误判为公网暴露。
- [ ] 用配置的可信 HTTPS origin 或严格允许列表生成订阅信息链接；测试伪造 Host/转发头、端口、错误 origin 和合法客户端兼容。不声称已存在可利用的跨用户攻击，除非验证出证据。
- [ ] 审查 API 进程对管理令牌、设备秘密、数据库和 agent socket 的权限，并说明现有边界；不要求现在拆分进程。
- [ ] 使用两个合成设备及多个链接覆盖令牌交换、跨格式请求、越权读取、撤销、重签发和管理员路径；保证响应、日志与证据不含其他设备秘密。

## 暂缓

复杂的订阅/管理进程拆分或权限系统在实际需要及迁移成本明确后评估；不把未拆分进程写成已完成隔离。

## Comments

2026-10-26：现有 Nginx 只转发订阅路径、API 监听本机；代码构造信息链接时使用请求 URL。代理和应用边界分别验收。
