# 02 降低重复生成成本

Status: deferred
Scope: planned
Priority: deferred
Blocked by: 01

## 问题

有效订阅请求会重新读取已发布配置并生成较大的客户端配置，可能被重复请求放大 CPU 和内存开销。

当前不要求实现缓存。先完成 01，只有正常订阅更新仍慢或资源占用高时再评估；以下是重新启动本任务时的要求。

## TODO 与验收

- [ ] 实现有限大小、有限存活时间的缓存、预编译公共部分或等效优化；多个并发请求可复用安全的工作，缓存不可被任意令牌无限扩张。
- [ ] 每次响应前重新确认订阅、设备、格式和期限；按设备凭据版本、发布 revision、格式及相关展示元数据隔离结果。撤销、到期、设备状态变化、密码轮换和发布更新后不可返回旧配置；并发竞态同样验证。
- [ ] 不保存明文令牌或跨设备复用完整敏感配置；如需要保存代理密码，定义私有权限、上限、清理及进程重启语义。保留 no-store 和原有客户端格式。
- [ ] 使用大规则集及合成设备进行冷/热缓存、并发、取消和失效测试；记录 CPU、内存及响应时间和测量条件，不将实验数据当作生产容量承诺。
