# 01 限制订阅请求和渲染并发

Status: done
Scope: software_and_authorized_ingress_deployment
Priority: must
Blocked by: none

## 问题

公开入口未配置请求/连接限额；未知令牌可重复请求，已知有效令牌还会触发昂贵的配置生成和传输，影响共享 CPU、内存及带宽。

## TODO 与验收

- [x] 按用户确认的方案，对订阅下载及信息页设置每来源平均 5 次/分钟、允许突发 5 次且不排队；全站同时最多 2 个订阅请求。无效和有效请求均受限，超出时返回 429。
- [x] 以连接实际来源地址限速；生产 Nginx 配置中未发现 real-IP 转发来源配置，隔离测试中伪造转发头不能绕过限流。同一 NAT 下的设备共享速率额度。
- [x] 在一次性、禁外网的 Linux 容器中用同版本 Nginx 和合成数据验证两个设备的正常下载与信息页、约 9.2 MB 配置、突发、并发上限、429 不暴露令牌及限流恢复；未触发生产超限测试。
- [x] 经用户明确授权部署到指定入口，保留原配置备份；生产 `nginx -t` 和重载通过，手机与 JXY 正常下载/信息页均为 200，内容与部署前一致。
- [x] 提供[部署与回退工具](../../../deploy/subscription_limits.py)和[操作说明](../../../docs/operations.md)；未修改宿主全局防火墙、路由或 VPN。生产异常恢复路径仅软件模拟，未做真实故障演练。

本次只实施用户确认的频率与并发方案，不增加新的请求体大小/超时策略、后台采样或通知。两个并发请求包含信息页；多人同时更新时额外请求可能暂时返回 429。正常请求验证不能保证真实客户端在任何网络条件下均不受影响，见[验证记录](../../../docs/validation/subscription-limits-2026-10-27/README.md)。
