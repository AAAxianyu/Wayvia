# 15 请求分阶段诊断

Status: open
Priority: P1

## 缺口

当前 HTTP 探针已有端点序号、总耗时、curl/HTTP 状态和错误分类，但 subprocess 超时可能只剩 HTTP_TIMEOUT 与空状态，无法区分连接、TLS、首字节或接收阶段。内部中继关闭与请求结果也必须独立记录。

## TODO 与验收

- [ ] 在原总预算内记录连接、TLS、首字节、总耗时、响应完成状态和有限错误分类；无相应阶段记录时标 unknown，不推断成功。
- [ ] 区分 curl 自身超时、外层进程期限、连接关闭、证书/身份失败和中继清理错误；在安全的范围内保留超时前已经取得的阶段数据。
- [ ] 不输出 stderr 原文、目标 URL、凭据、原始计划或响应体，不能因新增日志改变身份验证、备用策略及 fail-closed。
- [ ] 验证记录准确性、超时预算及脱敏；生产验收与软件回归分别记录，不凭错误名称认定具体网络节点。
